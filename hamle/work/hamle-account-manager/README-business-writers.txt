  create_task(payload, *, before_post=callback) -> {provider_id: str}

  create_comment(payload, *, before_post=callback) -> {provider_id: str}

  send_reply(payload, *, before_post=callback) -> {provider_id: str}
  read_reply(provider_id, payload) -> same verified readback flags

Dispatch owns human approval, immutable payload hash, authority snapshots, global stop,
budget deadline, permanent action lease and receipt ledger. Both writers require a
before_post callback after their slow credential and identity preflight. Dispatch must
perform its final stop/authority checks and durable begin_dispatch in that callback.
No write occurs if the callback is absent or raises. A request timeout or ambiguous
receipt must stay held; these adapters never retry. A deterministic MIME Message-ID
helps manual reconciliation, but does not guarantee provider deduplication.

Only Hamle -> Ahmet, exact internal subject HAMLE-IC-IS-20261010-01 and original
Gmail thread / RFC Message-ID are accepted. Gmail raw readback proves the Hamle Sent
copy; it does not prove delivery to Ahmet's inbox. No customer addresses are accepted.
recipient_policy permits Cansu in CC only when the latest actual source recipients
and human-approved envelope require it. Unknown recipients are held, never silently
dropped; Hamle/Ahmet are removed from CC during deterministic derivation. The writer
validates the bounded recipient set and checks the exact approved CC on readback.

The live verified existing task parent may be Todoset or Todolist. No new list is

Follow-up contract (local source; deployment is a separate step)
Only the bound task 10392247471 is accepted for status and comments. A work binding
contains account_id, project_id, task_id, todo_parent_id and todo_parent_type; the
store owns its immutable root/mail relationship. Status checks refresh identity,
private project membership and parent, then returns bounded plain description and
creator/assignee-scoped task state. Its fingerprint includes IDs, parent, title,
description, status, completed, due_on and assignees; updated_at and comment count
are excluded because our own comment may change them.

A comment payload has exactly account_id, project_id, task_id, todo_parent_id,
todo_parent_type, body (up to 4000 characters) and task_fingerprint. It cannot
change task assignment, deadline or completion. A fresh matching active/incomplete
task is required before the mandatory final before_post callback. Readback checks
the exact recorded comment ID, same task/project, Hamle creator, private status
and full approved text; it does not require the pre-comment fingerprint.

Official comments documentation, read 2026-10-10:

The fixed project-scoped comment routes remain supported. Creation posts content
and expects 201. Basecamp automatically notifies recording subscribers; there is

as exactly Ahmet/Hamle before these operations. No rich-text mention is created.

Gmail may replace a submitted RFC Message-ID with its own mail.gmail.com ID.
Readback permits only the requested header or one syntactically valid Gmail ID,
while checking the recorded REST receipt, mailbox identity, thread, full body and
all recipient/subject/reply-linkage headers independently. Deduplication remains
in the durable action ledger, never in the RFC Message-ID.
